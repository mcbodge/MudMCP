# Introduction

**Status**: 🟢 Completed
**Created**: 2026-10-20 · **Last updated**: 2026-10-21

Add a first-class CLI mode to the existing `MudMCP` .NET tool so coding agents query version-accurate MudBlazor documentation with terminal commands instead of MCP tools. Today `Program.cs` always builds a Generic Host (`--stdio`) or a `WebApplication` (default HTTP), every MCP turn carries about 2,100 tokens of tool schemas, and answers are verbose Markdown served from a 3.45 MB `index.json`. Target: `mudmcp <command>` is routed before any host is built, reads only the file it needs from a new split store written next to `index.json`, prints dense `compact` output by default (`markdown` and `json` on request), and ships with a ready-to-use Agent Skill. Approach: keep one project and one NuGet package, extract the shared query and Markdown-rendering code out of the MCP tools, add a zero-dependency command router, and write the CLI store as a by-product of every index build or cached load.

**Execution protocol**: run phases in order and start a phase only when the previous DONE-WHEN holds; tasks in a phase are independent unless one ends with `Depends: TASK-###`. On start, set the status line to `🟡 In progress`. After each validated task, set its Completed cell to ✅ and its Date to today; on resume, skip ✅ tasks. Replay each Playwright TEST marked `repro first: yes` before the first task it verifies and confirm the bug reproduces; after the fix, replay it to confirm the symptom is gone. When every task is ✅, set the status line to `🟢 Completed`. Update the **Last updated** line with each status change. Deliver only as the Delivery line says (`local`: stay on the current branch and never push), and commit this file on its own at the end of each run.

**Delivery**: local

**Out of scope**: auto-detecting the MudBlazor version from project files (ALT-011); RID-specific, ReadyToRun, or Native AOT tool packaging (ALT-007, ALT-008); `InvariantGlobalization` and GC-mode changes (ALT-009); changing the MCP server's default `DataPath` (`./data`), the `index.json` format, or `CacheSchemaVersion` (6); new or renamed MCP tools; bumping `<Version>` in the csproj (the release workflow sets it from the tag); Cursor-specific skill packaging (Agent Skills support in Cursor is unconfirmed).

- **REQ-021**: Name resolution — names are trimmed and cut at the first `<` (`MudSelect<T>` becomes `MudSelect`), then must be 1-128 ASCII letters, digits, or `_` (otherwise exit 2 `error: invalid name '...'`); component lookup is case-insensitive exact, then with a `Mud` prefix when the name lacks it (same rule as `ComponentIndexer.GetComponentAsync`, L524); enum lookup is case-insensitive exact (same rule as `GetEnumAsync`, L688).
- **REQ-022**: Member filter — `--filter` on `props`, `events`, `methods` takes comma-separated, case-insensitive glob patterns evaluated with `FileSystemName.MatchesSimpleExpression(pattern, name, ignoreCase: true)`; a pattern without `*` or `?` matches the exact name; a member is kept when any pattern matches. `examples --filter` keeps the MCP semantics (case-insensitive substring of example name, description, or any feature) through `ComponentExampleTools.FilterExamples`.
- **REQ-023**: Not-found hints — a missing component or type prints `hint: did you mean: ` plus up to 5 catalog names whose name contains the query or is contained in it, ignoring a leading `Mud` on both sides, ordered by length difference then name (ordinal-ignore-case); when the input is an enum name the hint is the exact `mudmcp enum` command line for it with `--version`; when no candidate exists the hint is the exact `mudmcp search` command line for the input with `--version`.
- **REQ-024**: Missing version — commands needing a version exit 2 with `error: MudBlazor version required: pass --version X.Y.Z or set MUDBLAZOR_VERSION`; the hint lists the ready versions under the data path (`hint: indexed versions: 9.0.0`) or, when none, `hint: read Version from <PackageReference Include="MudBlazor" ...> in your .csproj or Directory.Packages.props`.
- **REQ-025**: Not indexed — store-reading commands exit 3 when `IndexStore.IsCurrent(version)` is false, with `error: MudBlazor v9.0.0 is not indexed in ` plus the full data path, and the exact `mudmcp index --version 9.0.0` hint for the requested version.
- **REQ-026**: Query commands never clone, compile, or build an index; only `index` does. `index` deletes the version's `store` folder, runs `ComponentIndexer.BuildIndexAsync` composed through `McpServerHost.RegisterCoreServices` (derives the store from a valid `index.json` without cloning, or clones and parses when it is missing or stale), streams logs to stderr at Information level, and prints the `index-status` line for the version.

## 3. Alternatives

- **ALT-001**: Split into `MudBlazor.Mcp.Core` plus `Cli` and `Mcp` projects packed as one tool — rejected because the `Dockerfile` COPY lines, the `eng/azure-pipelines.yaml` project path, the AppHost `AddProject`, `MudBlazor.Mcp.slnx`, and the test project would all change, internals would need cross-assembly exposure, and a .NET tool package exposes one command, so no second consumer benefits; revisit only for a separate CLI-only Native AOT binary.
- **ALT-002**: System.CommandLine 2.0 (GA 2025-11-11, trim-friendly, AOT-capable) — rejected because it adds a package and its parsing and help pipeline to every cold start of a framework-dependent tool, its generated help is longer than the token-tuned help needed here, and 15 commands with about 15 options route through a short hand-written parser.
- **ALT-003**: ConsoleAppFramework (source-generated, reflection-free) — rejected because it adds a build-time dependency for a small, stable command surface.
- **ALT-004**: Keep the monolithic `index.json` and only switch it to minified, source-generated JSON — rejected because every query would still deserialize at least 1.77 MB (2.36 MB minified minus `ApiReferences`), the cost grows with each MudBlazor release, and slower machines get no headroom.
- **ALT-005**: SQLite with FTS5 — rejected because it ships native assets per runtime in the tool package, needs schema migrations, and ranks differently from `search_components`; 146 components need no full-text engine.
- **ALT-006**: MessagePack or MemoryPack binary cache - rejected because it adds a dependency and changes the persisted format; profiling must establish a worthwhile startup improvement before revisiting it.
- **ALT-007**: Native AOT for the whole tool — rejected because Roslyn, LibGit2Sharp, reflection-based `index.json` loading, and ASP.NET Core MCP hosting share the binary and are not AOT-safe, and trim or AOT warnings fail the build under `TreatWarningsAsErrors`.
- **ALT-008**: RID-specific tool packages with ReadyToRun (.NET 10 `ToolPackageRuntimeIdentifiers` plus an `any` fallback) - deferred because it multiplies packages and changes `.github/workflows/release-nuget.yml`; consider only when measured startup latency justifies the packaging complexity, not solely because the advisory PER-001 target is exceeded.
- **ALT-009**: `InvariantGlobalization` (skips ICU loading) and workstation GC — deferred because both change process-wide MCP server behavior (culture-aware default ordering, GC mode) that the Windows gate does not need; revisit together with ALT-008 using Linux or macOS measurements.
- **ALT-010**: Build the index automatically when a query finds no store — rejected because a multi-minute clone and Roslyn compile would run inside an agent's command timeout; explicit `index` plus exit 3 and a hint is deterministic.
- **ALT-011**: Detect the MudBlazor version from `.csproj` or `Directory.Packages.props` in the working directory — rejected because multi-project repositories would get silent wrong-version answers; the skill teaches the lookup and `--version` or `MUDBLAZOR_VERSION` stay explicit.
- **ALT-012**: A `--props-only` flag on `component` — rejected because it duplicates the `props` subcommand.
- **ALT-013**: An `IComponentIndexer` adapter over the store so the CLI calls the MCP tool methods directly — rejected because list and search rendering need full member lists and counts that a lazy adapter would fabricate or load in full; pure renderers over loaded data are simpler.
- **ALT-014**: Substring semantics for member `--filter` — rejected because `Color` would also return `IconColor`; globs give exact names by default and `*Color*` on request.

## 7. Risks & Assumptions

- **RISK-001**: The 50 ms budget is in-process; process wall-clock adds .NET runtime startup and, through `dnx`, the SDK CLI plus a NuGet feed check per call (dotnet/sdk#50579) — mitigation: `process-ms` is reported (PER-005), the global tool is the documented fast path (PER-006), and ALT-008 is the measured escalation.
- **RISK-002**: Deterministic tie-breaking (REQ-028) changes which components appear among tied search scores and which 10 related components MCP returns — mitigation: TEST-004 pins the order, docs/03 states it, and results become reproducible across runs.
- **RISK-003**: The MCP server and `mudmcp index` can write the same store concurrently — mitigation: each writer uses its own temp folder and a rename swap (SEC-003); a failed swap is logged as a warning, readers see a complete old or new store, or exit 3 for the instant between renames.
- **RISK-004**: A crash during a write leaves `store.tmp-` or `store.old-` folders — mitigation: the CLI never reads them, and `VersionCacheManager` eviction deletes the whole version folder.
- **RISK-005**: An existing `index.json` built with non-default parsing options (environment overrides) is rejected by `mudmcp index` when its environment differs, which triggers a re-clone — mitigation: `index` reads the same `appsettings.json` and environment variables as the server, so the same environment yields the same options.
- **RISK-006**: Renderer extraction could alter MCP Markdown — mitigation: TEST-005 to TEST-009 compare tool output with renderer output, existing tool tests stay unchanged, and TEST-003 checks a live response.
- **RISK-007**: Agent shells expand or mangle `*`, `?`, and `<` — mitigation: the skill and docs require quoting glob patterns, and REQ-021 strips generic suffixes.
- **RISK-008**: The gate is measured on one Windows machine — mitigation: `Measure-CliLatency.ps1` runs unchanged on Linux and macOS with `pwsh`; ALT-008 and ALT-009 name the follow-ups.
- **ASSUMPTION-001**: No `--http` argument exists today (`Program.cs` L11 only checks `--stdio`); the request to preserve "existing `--stdio` and `--http`" is met by keeping `--stdio` unchanged and adding `--http` as an alias of the default HTTP mode — basis: code read on 2026-10-20.
- **ASSUMPTION-002**: The requested ".github/copilot-instructions.md snippet in the repo" is a paste-ready block for consumer repositories (`docs/11-cli.md`) plus an update of this repository's own `.github/copilot-instructions.md` — basis: the user's wording covers both readings, and both are cheap.
- **ASSUMPTION-003**: The nominal 50 ms target measures in-process time with a warm OS file cache but a fresh process, so first-use JSON metadata and JIT work still count; process startup and `dnx` resolution remain separate. User approved technically justified overruns and startup profiling/optimization on 2026-10-21; do not substitute warm-process timings for fresh-process measurements.
- **ASSUMPTION-004**: `~/.mudmcp/v9.0.0/index.json` (schema 6, default parsing options, 146 components, 85 enums) stays on the dev machine for the Phase 4 to Phase 7 checks — basis: measured on 2026-10-20.
- **ASSUMPTION-005**: The packaged `appsettings.json` sits next to `MudBlazor.Mcp.dll` in the tool package, and `index` treats it as optional — basis: the server already reads it in dnx mode; `MudBlazorOptions` defaults equal its values.
